3. Planificación de Pruebas

3.1 Objetivos

  • Garantizar accesibilidad para todos los usuarios, validando contraste, navegación por teclado, textos alternativos y diseño responsivo del dashboard.
  • Asegurar la calidad previa a producción, comprobando que la API y la BD respondan correctamente antes del despliegue.
  • Identificar problemas tempranos y mejorar la calidad del código e interfaces mediante pruebas unitarias y de integración automatizadas.
  • Validar que el sistema cumple con los requisitos del negocio: extracción, moderación IA (Aprobado/Malo), síntesis de tendencias y métricas del dashboard.

3.2 Alcance

Dentro del alcance:

  • API REST: los 9 endpoints bajo /api/v1.
  • Lógica de moderación IA y su fallback local determinista.
  • Capa de repositorio y persistencia en MariaDB.
  • Interfaz web: navegación, filtros, moderación manual y Modo Demo.
  • Despliegue con Docker Compose (3 servicios).

Fuera del alcance:

  • Calidad interna del modelo DeepSeek (servicio externo de terceros).
  • Disponibilidad real de las fuentes externas (Dev.to / Hacker News).
  • Pruebas de penetración/seguridad avanzada.
  • Compatibilidad con navegadores heredados (IE11).

Observaciones generalesEl sistema desplegado en Docker se levantó con los 3 contenedores healthy. La API respondió correctamente en todos los contratos y validaciones, incluyendo el manejo de errores (404/422). La latencia de lectura fue excelente (media entre 10.7 y 16.3 ms, muy por debajo del umbral de 300 ms). El moderador IA operó de forma determinista mediante su fallback local (sin DEEPSEEK_API_KEY), y la cascada de extracción alcanzó a Dev.to real.
Recomendaciones
  • Ejecutar las pruebas de usabilidad/accesibilidad con Lighthouse y corregir el contraste de textos text-[10px] muy tenues.
  • Ejecutar las pruebas de esfuerzo con k6/Locust y ajustar DB_POOL_SIZE según la concurrencia observada.
  • Integrar la suite unittest a un pipeline de CI para regresión automática en cada cambio.
  • Añadir una prueba automatizada para la rama 400 de generate-trends (sin posts aprobados).
  • Corregir erratas de UI detectadas ("Moderaión", doble botón "Extraer") para pulir la experiencia.
  • Considerar medir cobertura con coverage.py para cuantificar la caja blanca.
